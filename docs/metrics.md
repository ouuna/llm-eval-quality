# 指标规范（Metrics Specification）

> 每个指标写清：定义 / 计算方法 / 输入 / 输出范围 / 阈值 / 优点 / 缺点 / 已知误差

**核心原则**：指标名不等于实际含义。`Lexical Similarity ≠ Semantic Similarity ≠ Factual Correctness`，`LLM Judge ≠ Ground Truth`。

---

## 1. Faithfulness（有据性 / 幻觉检测）

### 定义
回答中的每条事实陈述都能在给定上下文中找到依据。

### 计算方法（声明级验证，四步）

```
Step 1  声明抽取：按标点与并列词切分为原子声明
        "分为基础层、用例层、数据层、业务层" → 4 条独立声明
Step 2  逐条验证：每条声明与上下文各句算实词覆盖率，取最大值
Step 3  叠加检查：forbidden_facts 命中即判无依据
        数字冲突：声明中的数字若上下文不存在 → 判无依据
        否定冲突：一方含否定另一方不含 → 判无依据
        拉丁冲突：人名/术语若上下文不存在 → 判无依据
Step 4  跑题检测：所有声明与上下文零实词重合 → 判幻觉
```

### 阈值
- `supported_threshold` = 0.6
- `partial_threshold` = 0.35

### 输出
```
[0, 1]  1 = 所有声明均有依据
```

### 优点
- **能检出实体调换**（旧字符覆盖率的硬盲区）
- 粒度细，能定位到具体是哪条声明无依据
- 零成本、确定性

### 缺点
- 依赖字面重合，**同义改写可能误报**
- 实词提取基于字符过滤，**专有名词可能漏检**
- 对比型/整合型回答易误报（跨多个上下文片段）

### 已知误差
- 对比型回答（如"A 和 B 的区别"）被拆成跨片段的声明后会误判
- 语义等价但字面差异大的表述（如"包含"vs"分为"）会虚高覆盖率

## 2. Correctness（答案正确性）

### 定义
回答的事实与参考答案一致，且未出现禁止内容。

### 计算方法（四级递降）

```
Level 1  forbidden_facts 命中 → 直接判错
Level 2  required_facts 覆盖率 >= 0.7 → 正确
Level 3  acceptable_answers 最佳相似度 >= 0.7 → 正确
Level 4  仅 reference 时用相似度 → 降级，显式标注
Level 5  无任何依据 → 报"依据不足"，不编造分数
```

### 输出
```
[0, 1]  1 = 全部必需事实覆盖且无禁止内容
```

### 优点
- **能检出"答案错误但用词在上下文出现"**（旧实现的核心缺陷）
- 数字与实体可单独校验

### 缺点
- 依赖 `required_facts` 的标注质量
- 开放式问题难以穷举 required_facts

### 已知误差
- 标注不完整时会把正确答案判为错误
- `method=reference_similarity_degraded` 时判定依据较弱，报告中会显式标注

---

## 3. Completeness（完整性）

### 定义
问题要求的关键点是否全部覆盖。

### 计算方法
`required_facts` 中每项在回答中的实词覆盖率 >= 0.5 视为覆盖，统计覆盖率。

### 输出
```
[0, 1]  1 = 全部关键点覆盖
```

### 与 Correctness 的区别

| 指标 | 问的问题 |
|---|---|
| Correctness | 说得**对**不对 |
| Completeness | 说得**全**不全 |

典型反例：对比型问题只答一半 → 正确性无法判定，完整性低。

### 已知误差
- 未标注 `key_points` 的用例会跳过完整性判定（报告中标注"跳过"）

---

## 4. Relevance（相关性）

### 定义
回答是否在回应这个问题。

### 计算方法（三级递降，方向已修正）

```
Level 1  required_facts 覆盖率     ← 最可靠
Level 2  answer ↔ reference 余弦   ← 语义层
Level 3  answer ↔ context 覆盖率   ← 降级，显式标注
```

### ⚠️ 重要修正

**旧实现方向是错的**：

```python
# 旧（错误）：|question_chars ∩ answer_chars| / |question_chars|
#测的是"答案有没有抄问题里的字"
# 反例：问题「如何提高代码质量？」
#       答「代码质量的提高方法」→ 覆盖率 1.0，但这是废话
#       答「提高代码质量需遵循规范」→ 覆盖率 0.4，但这才对
```

新实现测的是"有没有答到被问的东西"。

### 输出
```
[0, 1]  1 = 命中全部被问要点
```

### 已知误差
- 拒答用例得 0 分，会拉低整体均值（报告中已说明）

## 5. Refusal Accuracy（拒答准确率）

### 定义
拒答行为是否符合期望。

### 两种失败模式（方向不同，修复方式不同）

| 模式 | 条件 | 严重度 |
|---|---|---|
| **false_answer** | 应拒答却作答 | 严重（编造内容） |
| **over_refusal** | 不该拒答却拒答 | 较轻（能力不足） |

拒答标记：`未提及`、`没有相关`、`无法回答`、`不知道`、`不明确`、`不存在于`、`参考资料中未`

### 输出
```
[0, 1]  1 = 拒答行为正确
```

---

## 6. Consistency（输出稳定性）

### 定义
同一问题多次作答的一致程度。

### 计算方法
- 重复 N 次（默认 3）
- 两两计算实词 Jaccard 相似度，取均值
- 同时记录 std / min / max

### ⚠️ 局限：文本相似 ≠ 事实一致

```
run_1: "等价类划分是……的子集"
run_2: "……的子集是等价类划分"     ← 字符级 Jaccard 0.97，表述已变

run_1: "回��测试是修改代码后重新执行"
run_2: "修改代码后需重新执行…这是回归测试"  ← 含义相同，Jaccard 低
```

**改进方向**：引入事实级一致性（对比关键事实是否一致），而非文本级。

## 7. Semantic Similarity（语义相似度，Embedding）

### 定义
文本在向量空间的语义接近程度。

### 计算方法
```
cosine(embed(a), embed(b))
```

模型：`embedding-3`（2048 维），通过 `EMBEDDING_*` 环境变量配置。

### 三种相似度

| 类型 | 用途 |
|---|---|
| `question ↔ answer` | 语义相关性 |
| `answer ↔ reference` | 语义正确性 |
| `answer ↔ context` | 语义有据性 |

### 优点
- **能识别同义改写**（词级的硬盲区）

### 实测对比（同义改写场景）

| 场景 | Lexical | Semantic | 分歧 |
|---|---|---|---|
| 同义改写 | 0.474 | **0.812** | 0.338 |
| 说错层 | 0.353 | **0.767** | 0.414 |
| 完全跑题 | 0.000 | 0.379 | 0.379 |

### 缺点
- 粒度粗，**能说"话题相关"但无法定位具体声明**
- 成本高（每次调用一次 API）
- API 不可用时必须返回 `unavailable` 而非回退

### 关键边界
> **语义相关度不能单独判定幻觉**："多出一层业务层"的语义相似度 0.773，与正确答案 0.794 差别很小。最终幻觉判定必须以声明级验证为准。

## 8. LLM Judge

### 定义
用 LLM 对输出做多维度质量判定。

### 五维评分
`faithfulness` / `relevance` / `correctness` / `completeness` / `coherence`（各 0-5，归一化到 0-1）

### Judge Bias 控制

| 偏差 | 控制手段 | 实测 |
|---|---|---|
| 长度偏好 | Prompt 明确"不要因更长就给高分" | — |
| 肯定倾向 | 强制要求 `evidence` 字段 | 有 |
| 刻度漂移 | `temperature=0` + 重复验证 | spread=0.000 ✅ |
| 位置偏好 | 交换顺序对比 | effect=+0.28 ⚠️ |
| 自我偏好 | Judge 模型可配置 | **未验证** ⚠️ |

### 已知局限（重要）

**Judge 会漏判实体调换**：

```
上下文：基础层…用例层…数据层
回答：  基础层、用例层、报告层
Judge： score=0.72，hallucination=False
原因：把"事实冲突"理解为"资料未提及"（信息缺失）
```

**结论：Judge 不能单独作为幻觉判据，必须与声明级验证交叉验证。**

## 9. 性能与成本指标

| 指标 | 定义 |
|---|---|
| `p95_latency_ms` | 延迟的 95 分位 |
| `avg_cost` | 平均成本 |

**不可用时必须记 `unavailable`，不得填 0**。填 0 会让均值失真，违反"不要伪造数据"。

## 指标间的自洽性检查

**指标之间应该自洽**。若出现矛盾，说明至少有一个指标定义错了。

项目审计阶段曾发现：

```
域内准确率 100%
平均相关性 0.51        ← 矛盾
```

当时"域内准确率"根本不测正确性，只是幻觉检测的变体。**修正后两者才自洽。**

> **自洽性是发现指标造假/失准的最有效手段。**

## Quality Gate 阈值

见 `configs/quality_gate.yaml`。分四层：

| 层 | 含义 | 阈值特点 |
|---|---|---|
| `critical` | 能力底线，不达标必须阻断 | 严格（域外拒答 = 100%） |
| `quality` | 质量目标 | 允许小幅不达标 |
| `performance` | 性能与成本 | 按项目调整 |
| `stability` | 稳定性 | 按场景调整 |

**指标不可用时门禁跳过而非失败**（不可计算 ≠ 不达标），但报告必须显式说明跳过原因。
