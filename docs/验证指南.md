# 验证指南 —— 从零跑通本项目

> 目标读者：第一次拿到这份代码的人。照着本文一步步走，即可确认项目在你的机器上能正常安装、启动、跑评测，并排查最常见的故障。
>
> 全程约 10 分钟；其中「不花钱的离线验证」只需约 5 分钟。

---

## 一、环境准备

### 1.1 硬性要求

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Windows / macOS / Linux 均可 | 本文命令以 Windows 的 `cmd` 为例 |
| Python | **3.9 或更高** | 3.9~3.13 均可，推荐 3.10+ |
| 网络 | 跑真实评测时才需要 | 离线验证不联网 |
| API Key | 跑真实评测时才需要 | 离线验证不需要 |

### 1.2 确认 Python 已装好

打开 **cmd**（不是 PowerShell），执行：

```cmd
python --version
```

期望看到类似 `Python 3.11.x`。若提示 `'python' 不是内部或外部命令`，说明 Python 没装或没加进 PATH，先去 [python.org](https://www.python.org/downloads/) 下载安装，安装时**勾选「Add Python to PATH」**。

> 如果电脑上装了多个 Python（常见于用 `conda`、便携版或 IDE 自带的），务必记住**用哪个解释器跑就用哪个装依赖**。后文「常见问题 1」会详细说明。

## 二、获取代码与安装依赖

### 2.1 获取代码

```cmd
git clone https://github.com/ouuna/llm-eval-quality.git
cd llm-eval-quality
```

仓库是公开的，不需要登录。

### 2.2 安装依赖

```cmd
pip install pytest
```

**就这一个。** 项目核心代码**零第三方依赖**，全部用 Python 标准库实现（连 YAML 解析都是自己写的子集）。`pytest` 是唯一必需项，用于跑测试。

> `requirements.txt` 里列了 PyYAML、openai、deepeval 等「可选增强」，**都不是运行必需**，默认不用装。

### 2.3 验证依赖装对了

```cmd
python -m pytest --version
```

能打印出版本号（如 `pytest 8.x`）即成功。若报 `No module named pytest`，见「常见问题 1」。

## 三、三步快速自检（不花钱、不联网）

这一步不配置任何 API，纯离线，最快确认「项目本身是好的」。

### 第 1 步：列出数据集

```cmd
python -m eval list
```

**期望输出**：一个数据集列表，包含 `smoke`、`full`、`extended`、`coverage`、`regression_bugs`、`gold_set` 等，每条带条数。

### 第 2 步：跑一次离线评测

```cmd
python -m eval run --dataset smoke --mock
```

`--mock` 用内置假模型替代真实 API，不花钱、不联网。

**期望输出**：一段评测总结 + 门禁结果。门禁显示 `FAILED` 是**正常现象**——因为 Mock 会故意「答错」域外问题，评测器正确地把它们拦下来了。若这里显示全 PASS，反而说明门禁坏了。

### 第 3 步：跑离线测试

```cmd
python -m pytest tests/ -q
```

**期望输出**：`600+ passed`，末尾没有 `FAILED`。`xfailed`（预期失败）和 `skipped` 都是正常的。

**这三步全部走通 = 项目在你的机器上可以正常工作，无需任何 API 配置。**

## 四、核心功能逐一验证

下面按「功能 → 验证命令 → 怎么看结果算通过」逐项列出。建议按顺序走一遍。

### 4.1 配置查看（密钥脱敏）

```cmd
python -m eval config
```

**通过标准**：能打印出 API Key（打码）、接口地址、模型名。即使还没填 Key，也会显示「缺哪些项」。

### 4.2 数据集合法性校验

```cmd
python -m eval validate --dataset full
python -m eval validate --dataset coverage
```

**通过标准**：输出「校验通过，无问题」。这一步能提前发现数据集写错（缺字段、拒答类误给参考答案等）。

### 4.3 评测器可靠性（Gold Set 反向测量）

```cmd
python -m eval.evaluators.validation
```

**通过标准**：输出混淆矩阵（TP/FN/FP/TN）和 Precision / Recall / F1 / FPR / FNR。Recall 应接近 100%（漏报控制）。注意报告会如实说明「Gold Set 为单标注者，存在乐观偏差」——这是已知局限，不是 bug。

### 4.4 变异测试（查漏报）

```cmd
python -m eval.mutation
```

**通过标准**：输出各变异类型的检出率，总体约 95%。其中「因果倒置」「时序错乱」检出率 0% 是**已知盲区**，报告会明确标注，不是故障。

### 4.5 阈值校准

```cmd
python -m eval.calibrate
```

**通过标准**：输出一张「阈值 → 准确率/精确率/召回率/F1」的对照表。

### 4.6 指标定义与阈值一览

```cmd
python -m eval.thresholds
```

**通过标准**：列出 15 项阈值及其来源（heuristic / observed），并说明这些是「工程初始值」。

### 4.7 检索召回率回归（离线）

```cmd
python -m pytest tests/test_retrieval_recall.py -q
```

**通过标准**：3 项测试全通过。它钉死了「answer 类用例的检索召回完整率为 100%」这一结果，防止检索逻辑改坏。

### 4.8 被测系统 HTTP 服务（手动启动）

```cmd
python -m app.server
```

**通过标准**：打印出服务地址（如 `http://127.0.0.1:8765`）和 `GET /health`、`POST /ask` 两个接口。另开一个 cmd 验证：

```cmd
curl -s http://127.0.0.1:8765/health
```

返回正常即服务起来了。按 `Ctrl+C` 停止。

> 这是「被测系统」本身，不是评测框架。评测框架通过 `--dataset` 调用它，也可以单独起这个服务做手动调试。

## 五、配置真实 API（跑真实评测）

离线验证都通过后，如果想看真实模型的表现，再配 API。

### 5.1 用项目内配置文件（推荐）

在项目根目录：

```cmd
copy env.example .env
```

用记事本打开 `.env`，把 `EVAL_API_KEY=` 后面填上你的 Key，保存即可。

**为什么用 `.env` 而不是系统环境变量**：`.env` 只对本项目生效，不会和你电脑上其他 AI 工具（它们也在用 `OPENAI_API_KEY` 这组名字）互相覆盖。`.env` 已在 `.gitignore` 里，不会被提交，密钥不会泄露。

### 5.2 确认配置生效

```cmd
python -m eval config
```

重点看「生效的变量名」那一行：
- 显示 `EVAL_API_KEY` → 走项目配置，正确
- 显示 `OPENAI_API_KEY` → 还在读系统变量，建议改成 `.env` 方式

### 5.3 跑真实评测

```cmd
python -m eval run --dataset smoke
```

第一次跑约 1~2 分钟（多次 API 调用）。跑完会在 `reports/` 生成 `report.html`、`eval_results.json`、`eval_report.csv` 三份报告。

## 六、常见故障排查

### 问题 1：`No module named pytest`

**原因**：pytest 装在了别的 Python 环境里，而你现在用的这个 Python 没装。

**排查**：
```cmd
where python
```
会列出所有 Python 的路径。

**解决**：用装了 pytest 的那个解释器显式运行：
```cmd
D:\python\python.exe -m pytest
```
或者给当前这个 Python 也装一遍：`python -m pip install pytest`。

### 问题 2：`CONFIGURATION ERROR` / 缺环境变量

**原因**：跑真实评测时没配 API Key，或配了但没生效。

**解决**：
1. 确认 `copy env.example .env` 已执行、`.env` 里 Key 已填；
2. 用 `python -m eval config` 确认「生效的变量名」；
3. 若用 `setx` 配过系统变量，**重开命令行窗口**再试；
4. 先 `--mock` 模式确认项目本身能跑，再排查 API 配置。

### 问题 3：`No module named yaml` 之类

**不会发生**——项目用自研的轻量 YAML 解析，不依赖 PyYAML。若真见到，说明有代码路径误用了 PyYAML，属于 bug，请反馈。

### 问题 4：数据集校验报错

**原因**：`eval validate` 发现数据集写错了。

**看报错**：它会精确指出是哪条用例、什么字段有问题（如「域外用例不应有 expected_output」）。

**解决**：按提示改数据集，或对照 `eval/datasets/` 里现有用例的写法。

### 问题 5：门禁显示 FAILED，是不是我环境有问题？

**不是。** 门禁 FAILED 是**正常结果**——被测的 RAG 系统本来就有幻觉（实测幻觉率约 12.5%），评测器把它拦下来是正确行为。

只有**退出码是 2/3/4** 才代表真的出问题了：
- `2` 配置错误（缺环境变量）
- `3` 数据错误（数据集/用例不存在）
- `4` 运行时错误

`0`（通过）和 `1`（门禁未通过）都是「系统正常、只是质量好坏」的范畴。

### 问题 6：报告文件找不到

**原因**：`reports/` 下的 `report.html`、`eval_results.json` 等是**运行后生成的**，不是仓库自带。

**解决**：先跑一次评测（`python -m eval run --dataset smoke --mock`），报告才会生成。

### 问题 7：真实评测报 429（限流）或 401/403（鉴权失败）

**429**：调用太频繁，程序会自动退避重试，一般等等就好。

**401/403**：Key 错误或没开通该模型的权限。检查 `.env` 里的 Key 是否正确、是否开通了对应的模型。

## 七、提交前自检（开发者用）

改完代码、准备提交前，跑这两个工具，能提前发现「本地全绿、CI 挂」的差异：

```cmd
python -m tests.check_undefined_names   # 约 1 秒，防版本差异
python -m tests.simulate_ci            # 约 30 秒，防配置差异
```

两个都通过再提交。它们存在的理由是：这个项目曾因「本地 Python 3.14 宽松、CI 3.11 严格」和「本地有 .env、CI 没有」各挂过一轮。
